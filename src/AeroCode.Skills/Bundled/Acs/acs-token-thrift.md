# Token Thrift：输入侧才是成本主项

来源事实：某 Agent 实测总消耗 13,995,350 token，其中**输入 token 13,718,510，占 98%**。省 token 的战场在**输入**，不在输出。少写字省不了钱，少回灌才省钱。

`[软约束]` 本技能全部为纪律性约束（Context 层）。`[硬约束]` 部分由 `gate_loop_guard.py` 检查 `context_bytes_proxy` 与 `refeed_full_history`。

`[降维实现]` agent 侧无法向平台独立核账，本技能默认度量用代理指标（`*_proxy`：引用字节数、读取文件数、步数、请求数），不谎称精确 token 数。
但 proxy 不得从「权宜」变成「永久」：拿得到真账时必须按第 7.5 节回填 `cost_metering`。

## 1. 五条策略（按收益排序）

| # | 策略 | 做法 | 收益来源 |
| --- | --- | --- | --- |
| 1 | 禁止回灌 No-Refeed | 跨步只传 ≤1000 字压缩总结 + 状态文件路径 | 直接砍掉占比最大的重复输入 |
| 2 | 状态外置 State Outside Context | 权威状态写 `task-state.json`，不靠对话记忆 | 上下文不再随任务长度线性膨胀 |
| 3 | 渐进披露 Progressive Disclosure | 先读目录/索引/签名，命中后才读正文；技能只加载入口，需要时再读 reference | 避免「为看一行读整个仓库」 |
| 4 | 稳定前缀 Stable Prefix | 前缀内容严格不变，变动内容全部放到末尾 | 命中 prompt cache：读取按 0.1× 计费（省约 90%），TTFT 降约 85% |
| 5 | 洁净续跑 Clean-Context Continuation | 上下文接近上限时不摘要整段历史，而是重新从状态文件冷启动 | 断掉历史雪球 |

## 2. 稳定前缀纪律（缓存命中的硬要求）

缓存机制按前缀精确匹配，**前缀里任何一个字符变了，整段缓存作废**。因此：

**禁止进入前缀**：当前时间/时间戳、随机 ID、自增计数器、每轮变化的进度百分比、剩余轮数、"第 N 次尝试"。

**正确的排布顺序**：

```
[固定] 系统纪律 / 技能正文 / 项目规则 / 稳定的项目背景
[固定] 长期不变的参考资料
------------------------- 以上为可缓存前缀，绝不改动
[变动] 本轮状态摘要、本轮目标、本轮输入
```

写入缓存有约 1.25× 的一次性溢价，命中读取约 0.1×。**结论：同一前缀至少要被复用 2 次以上才划算**；一次性任务不必刻意构造前缀。

## 3. 读取预算（渐进披露的可执行规则）

| 顺序 | 动作 | 预算 |
| --- | --- | --- |
| 1 | 目录/文件名/符号列表 | 无限制（廉价） |
| 2 | 正则/关键字检索定位 | 优先，命中行 ±20 行上下文 |
| 3 | 读单文件的指定行段 | 默认 ≤200 行 |
| 4 | 读整个文件 | 仅当文件 ≤400 行或确需全貌 |
| 5 | 读多个文件全文 | 必须先说明理由；≥5 个文件时改为派子代理并只取摘要 |

铁律：**先检索定位，再定点读取**。禁止「先把相关文件都读一遍再想」。

## 4. 压缩总结模板（≤1000 Unicode 码点，固定三段）

v2.1 起每步交接覆盖写入 `.acs/handoff.md`。T2+ 由 `gate_checklist.py` 强制绑定当前 `task_id` 与 `steps[]` 最新 `id`，并机检「当前目标 / 已完成 / 下一步」三个精确段落；已完成必须含证据，下一步必须含完成标准。全量状态仍在 `task-state.json`（无损），本总结只防跑偏。

```
task_id: <当前 task_id>
step_id: <最新 step id>

## 当前目标
<一句话目标>

## 已完成
- <文件路径 + 关键行为>｜证据：<命令/断言及真实结果>

## 下一步
- <唯一下一动作>｜完成标准：<命令/文件/断言>
```

纪律：

- **只写结论与证据，不复述过程与推理**。推理已消耗过一次，不值得再消耗一次。
- 引用一律用路径 + 行号，不粘贴大段原文。
- 数字必须是真实测得值；写不出真实值说明这一步未验证。
- 超过 1000 字 → 说明这一步拆得太粗（回到 `loop-engineering` 窄步闸）。

## 5. 洁净续跑（Clean-Context Continuation）

上下文接近上限或被截断时：

1. **不要**把历史对话摘要成一大段塞回去（那是把污染压缩后再吃一遍）。
2. 冷启动加载三样，仅此三样：
   - `task-state.json`（权威状态：DAG、当前节点、已完成、待办）
   - 最近**一条**压缩总结
   - 当前节点契约指向的具体文件
3. 重新读文件确认真相，**不信任记忆中的文件内容**（文件可能已被改过）。

## 6. 高频浪费模式（自查）

| 浪费 | 症状 | 改法 |
| --- | --- | --- |
| 历史回灌 | 每轮开头复述前面做了什么 | 只给状态文件路径 + 一条总结 |
| 全量读取 | 为改一行读了整个模块 | 先检索定位再定点读 |
| 重复确认 | 反复读同一文件确认同一事实 | 结论记入状态文件，之后引用 |
| 礼貌性输出 | 大段铺垫、免责、复述需求 | 直接给结论与证据 |
| 无进展推理 | 长时间思考不动手（思考占比 >0.40） | 改写最小可执行验证（见 `loop-engineering`） |
| 前缀污染 | 每轮把时间戳/轮次塞进开头 | 挪到末尾变动区 |
| 技能全装 | 一次加载所有技能与参考文件 | 主入口 + 按需加载 reference |

## 7. 度量与自检（代理指标）

每步记入 `task-state.json`：

```json
{"context_bytes_proxy": 8200, "files_read_proxy": 3, "refeed_full_history": false,
 "summary_chars": 380, "think_ratio": 0.31}
```

预警线：`context_bytes_proxy` 单步 > 20000、`files_read_proxy` 单步 > 5、`summary_chars` > 1000、`refeed_full_history = true` → 由 `gate_loop_guard.py` 判 BLOCK。

**禁止为了让指标好看而漏记**，漏记等同造假。

## 7.5 真账回填：`cost_metering`（能拿到就必须回填）

proxy 不是计量，只是可测的替代物。一些终端确实能拿到真账（API usage 回包、CLI 的 usage 命令、UI 上的用量面板）—— 能拿到却不回填，降维就从「权宜」变成了「永久」。

写入 `task-state.json` 顶层（不是写在 step 里）：

```json
"cost_metering": {
  "source": "api_usage",
  "tokens_actual": 128340, "input_tokens_actual": 121600, "output_tokens_actual": 6740,
  "evidence_ref": ".acs/usage/2026-08-27-run.json（usage 落盘，可逐条复查）"
}
```

四条纪律（由 `gate_loop_guard.py` 机检，阈值见 `spec/thresholds.json` 的 `cost_metering`）：

1. **T2+ 必须显式声明 `source`**。可选：`unavailable` / `self_reported` / `terminal_ui` / `api_usage` / `cli_usage`。拿不到真账就写 `unavailable` —— **沉默不算声明**。
2. **声称可审计（`api_usage` / `cli_usage`）就必须给数字 + 可复查证据**。`evidence_ref` 要的是路径或取数命令，**「已确认无误」这类空话一律判无效**。
3. **来源不可审计时禁止出现 `tokens_actual`**。只能留在 `*_proxy` 字段里 —— **字段名本身就是诚实声明**，改叫 `actual` 就是冒充计量。
4. **有真账就按真账拦**：`input + output` 必须对上 `tokens_actual`；总量超分级上限（T1 100k / T2 400k / T3 1.2M）即判成本失控。上限取自反面基线：同框架对照模型 9 个任务共 956,630 token（均 ~106k/任务）。

拿不到真账时的正确做法是 `{"source": "unavailable", "note": "..."}` 并删掉所有 `*_actual` 字段。**编一个数字比声明拿不到严重得多。**

## 8. 与其他层的边界

- 何时停止循环 = `loop-engineering`；如何切分并隔离子任务上下文 = `graph-engineering`；本技能只管**每轮喂进去什么**。
- 省 token 不得牺牲正确性：真实性验证、独立验证、门禁脚本**一律不许以「省 token」为由跳过**。省下的 token 若换来一次返工，是净亏。
