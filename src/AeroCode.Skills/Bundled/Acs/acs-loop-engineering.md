# Loop Engineering：把「继续/停止」变成可机检的契约

Loop 层只回答一个问题：**这一轮之后，继续还是停止？** 判定必须来自证据，不来自感觉。

`[软约束]` 本文档是纪律；`[硬约束]` 是 `scripts/gate_loop_guard.py` 的退出码。两者冲突时以脚本为准。

## 1. 反面基线（为什么必须设闸门）

某 27B 开源模型接入 harness 跑 9 个 Agent 任务的实测数据：

| 指标 | 该模型 | 对照模型 | 倍数 |
| --- | --- | --- | --- |
| 总 token | 13,995,350 | 956,630 | 14.6× |
| 其中输入 token | 13,718,510（占 98%） | 927,401 | — |
| 总耗时 | 22,564s（6h17m） | 1,343s | 16.8× |
| 单题（3D 网站）token | 11,533,959 | 161,019 | 71.6× |
| 单题请求数 / 耗时 | 124 次 / 18,639s | 15 次 / 541s | 8.3× / 34× |
| 单题 step / turn | 75 step / 3 turn | 8 step | — |
| 思考时间占比 / 思考 token 占比 | 55.6% / 60.7% | 29.6% / 36.6% | — |
| 「其它运行时间」占单题总时长 | 59%（12,632s） | — | — |

四条根因，逐条对应下文一道闸门：

1. **单步目标过重** → 窄步闸
2. **完成标准不清晰** → 停止协议
3. **上下文反复回灌**（输入 token 占 98%）→ 回灌禁令
4. **空转**（拆 75 步却大量时间不产出）→ 空转闸 + 思考预算闸

结论一句话：**拆得多不等于拆得好。** 步数不是指标，单步的「上下文体积 + 完成标准」才是。

## 2. 停止协议（Stop Protocol）

一轮结束时按顺序判定，命中即停：

| 优先级 | 条件 | 判定 | 后续 |
| --- | --- | --- | --- |
| 1 | 硬门禁 BLOCK（退出码 1） | 未完成 | 修复后重跑同门 |
| 2 | `evidence_delta = 0` 连续 2 轮 | 空转 | 停止并升级，禁止同法第三次 |
| 3 | 达到安全阀（轮数/预算/时长任一） | 强制中断 | 写交接总结 + 上报 |
| 4 | 全部 `acceptance` 断言由**独立验证者**核验通过 | 完成 | 进入下一门 |
| 5 | 以上皆否 | 继续 | 写压缩总结后进入下一轮 |

**不信自报完成**：`claimedDone` 只是待验证信号，永远不是准出依据。核验者必须与执行者不同身份（`verifier != builder`）。

**完成标准必须可机检**，三类之一，其余写法一律无效：

- 命令类：`pytest tests/x.py -q` 退出码 0
- 文件类：`path/to/f.json` 存在且含字段 `k`（真实 FS 读回，不看工具回执）
- 断言类：某数值/文本比对成立（给出实际值，不只写「符合预期」）

无效写法：「功能正常」「已完善」「应该可以了」「逻辑无误」。

## 3. 四道成本闸门（硬阈值）

| 闸门 | 阈值 | 机检字段 | 违反动作 |
| --- | --- | --- | --- |
| 窄步闸 Narrow-Step | 单步 **1 个** 可验证产出；15~30min；acceptance 属上述三类 | `outputs`、`budget_min`、`acceptance[].kind` | 拆分该步后重新开工 |
| 回灌禁令 No-Refeed | 跨步只传 ≤1000 字压缩总结 + 状态文件指针；`refeed_full_history` 必须为 false | `context_bytes_proxy`、`refeed_full_history` | 改读 `task-state.json` + 摘要，不复述历史 |
| 空转闸 Spin Detector | two-strike：连续 2 轮 `evidence_delta = 0` | `evidence_delta` 序列 | 立即停 → 换方案或问主人 |
| 思考预算闸 Think-Budget | `think_ratio ≤ 0.40` | `think_ratio` | 停止推理，改写最小可执行验证 |

`evidence_delta` 的合法计量（三者任一 >0 即算有进展，必须可核验）：

1. 文件变更数（新增/修改的真实字节差）
2. 新通过的断言数（此前失败、现在通过）
3. 新获得的外部事实数（有来源可引用）

**重述、改措辞、重跑同一条已通过的命令、再想一遍，都不算证据。**

思考占比降不下来时的替代动作（按序尝试）：写一个最小复现脚本 → 打印真实中间值 → 二分定位 → 仍不清楚则上报缺口。

## 3.5 有界重试（v1.1：重试是空转的另一种形态）

FinBot 实战教训：生成→报错→原样再生成，是永动机不是修复。重试与空转同源 —— 空转闸拦「无新证据的轮次」，本节拦「有次数却无变化的重复」。四条规矩（由 `gate_loop_guard.py` 机检，阈值见 `spec/thresholds.json` 的 `retry` 节）：

1. **有上限**：`steps[].retries` ≤ `max_retries`（默认 2）。同法重试超过上限就该换路，不是再来一次。
2. **留痕**：`retries > 0` 必须写 `retry_reason`（为什么值得再试一次）。重试不写原因等于掩盖失败。
3. **声明变化**：`retries > 0` 必须写 `delta_from_last`（这次与上次差在哪）。说不清差在哪，就是同法重试。
4. **不登记就视为首次**：`retries` 缺省不报错，但一旦登记就必须遵守上述全部规矩；拿「不写字段」绕闸门，等于自报无重试，与 two-strike 空转闸互为备份。

与第 5 节 loop-until-dry 的关系：那里的收敛判据是「扫描不再出新候选」，这里的收敛判据是「同一动作不再出新变化」——同一个思想的两个切面。

## 4. 安全阀（Circuit Breaker）

每个循环启动前必须先声明上限，缺一即为违规：

```
max_rounds        默认 T1=3  T2=6  T3=10
max_requests_proxy 默认 max_rounds × 4
max_minutes       默认 T1=15 T2=45 T3=120
on_break          必须写：交接总结 + 未完成清单 + 建议下一步
```

触发安全阀不是失败，**隐瞒触发才是失败**。中断必须如实上报，并给出已完成/未完成边界。

## 5. loop-until-dry（批量清扫收敛）

用于「扫描—修复—再扫描」类任务，防止无限循环与漏扫：

```
seen = 集合（幂等键）
dry_rounds = 0
每轮：
  candidates = 扫描() - seen
  若 candidates 为空：dry_rounds += 1；否则 dry_rounds = 0
  处理 candidates（逐个记入 seen）
  若 dry_rounds >= 2 或 触发安全阀：退出
```

- **幂等键**必选稳定标识（文件路径 + 内容 hash / 规则 ID），禁止用序号或时间戳。
- 每轮必须**重新扫描**，不复用上一轮的清单（否则漏掉本轮新引入的问题）。
- 需要 `dry_rounds >= 2` 而非 1：一轮空可能是扫描口径出错。

## 6. 重入与幂等

- 所有循环状态写 `task-state.json`，不靠对话记忆（对话会被截断、会被压缩）。
- 每轮开始先读状态文件，**以文件为真相源**；工具回执与记忆不可信。
- 写操作必须可重放：先判存在与内容一致，一致则跳过并记 `skipped`。
- 中断后续跑走「洁净续跑」：只加载状态文件 + 最近一条压缩总结，不重放历史对话（见 `token-thrift`）。

## 7. 每轮交接总结（≤1000 Unicode 码点，省 token 主力）

v2.1 起每轮覆盖写 `.acs/handoff.md`。T2+ 由 `gate_checklist.py` 强制：绑定当前 `task_id` 与 `steps[]` 最后一项 `id`，三个精确段落各出现一次且非空；「已完成」含证据，「下一步」含完成标准。缺任一项或超过 1000 Unicode 码点即 BLOCK：

```
task_id: <当前 task_id>
step_id: <最新 step id>

## 当前目标
<一句话目标>

## 已完成
- <文件或事实>｜证据：<命令/断言及真实结果>

## 下一步
- <唯一下一动作>｜完成标准：<命令/文件/断言>
```

## 8. 与其他层的边界

- 单个节点内的「继续/停止」= 本技能；节点之间的依赖与并行 = `graph-engineering`。
- 候选打分与排序 = `self-verify-scaling`；本技能只消费其分数做方向偏离检测（分数连续不升视为 `evidence_delta = 0`）。
- 上下文压缩与状态外置的具体写法 = `token-thrift`。

## 9. 硬门禁

```
python -X utf8 <SUITE>/scripts/gate_loop_guard.py --state .acs/task-state.json --tier T2
```

退出码 0=PASS，1=BLOCK（打印违规步与字段），2=USAGE_ERROR（视为未验证=未完成）。
